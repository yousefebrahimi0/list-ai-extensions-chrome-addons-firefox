This document accompanies the README refresh. **It is not a functional or security certification.** Store presence, release version, permissions and publisher identity were checked where indexed store pages were accessible; some Chrome Web Store results are inaccessible to automated browsing, and cached store snapshots can lag current releases. Version labels in the README are deliberately limited to independently corroborated snapshots.

## Privacy-focused review priorities

| Existing entry | Security/maintenance concern | Suggested action |
|---|---|---|
| Glasp YouTube Summary (Firefox) | Requests access to data for all websites | Review privacy policy and limit website access where supported |
| ChatGPThing (Firefox) | Very small user base and broad page access on old listing | Recheck maintenance and owner; consider removing |
| Typli.ai (Firefox) | Very small user base on old listing; broad access | Recheck publisher and maintenance |
| Scraper.AI (Firefox) | Can read website contents; broad permissions can be inherent to scraping | Verify the business and data-use policy |
| Qalam (Firefox) | Older release and potential wide access | Review before recommending |
| Ellie (Firefox) | Email content permissions across Gmail, Outlook, and Fastmail | Treat as sensitive even with a recognized publisher |
| HARPA / automation assistants | Browser automation and full-page extraction have high impact | Prefer explicit activation, test profiles, and restricted site access |
| AI plagiarism/content detectors | False positives are possible | Describe results as probabilistic, not proof |

**Security interpretation:** These are risk flags, not findings of malicious software. An extension may genuinely need all-sites access to implement a global selection or rewriting feature. Still, permissions should be evaluated alongside developer provenance, code auditability, recency, privacy practices and potential server-side transfer of page or email data.
